# 0002：可选原生 Clang 捕获证据

状态：采集原型；不改变默认分析与部署门控。

## 背景

Clang JSON AST 的 lambda body DeclRef 保留词法声明，闭包字段没有显式关联
捕获变量的 ID 边。同类型多捕获不能靠名称或类型配对；外层按值、内层按引用
的执行反例说明词法 ID 也不能直接解释为最外层运行时对象。

## 决策

新增可选 Clang 插件，使用 `getCaptureFields`/`LambdaCapture` 原生 API，
在同一 ASTContext 中输出完整 JSON AST 与捕获元数据。调用者显式提供与
编译器兼容的插件；不自动安装工具链，不把插件加载到默认源码采集路径。

声明、字段、lambda、初始化表达式 ID 仅在单个 envelope 内有效。不同编译
进程的 AST 不得用裸地址 ID 连接。采集入口保存插件/编译器/源文件哈希、
命令、原始诊断与同次依赖观测；依赖观测仍不是冻结输入快照。

## 保证边界

插件成为可选前端的可信组件，不是独立语义 checker。采集成功只表示获得
关系证据，不建立运行时源对象身份、生命周期、无写历史或 launch 等价。
init-capture、this、VLA 等不支持情况保留明确记录，不静默忽略。
嵌套路径必须保留，以供后续逐层检查；不能跳过外围按值捕获。

## 代价与替代方案

原生插件需要匹配 Clang 开发库和 ABI；普通 CPU 检查仍可不安装它。
专项 CI 构建并运行匹配插件，避免全部测试静默跳过。
拒绝用字段顺序观察、源码 offset 或名字猜测映射；单字段特判也不作为
通用多捕获路径的替代。后续如迁移独立 tooling executable，仍保持同次采集边界。
