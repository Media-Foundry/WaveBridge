# 先检查复制结构，再建立条件值关系

日期：2026-09-26。状态：采用。

## 问题

复制字段的值相等需要源存活、字段已初始化且可读等前提。若构造器效果分类
只能从该值关系成功报告产生，就不能再用它反向证明源存活。真实构造器可经
自己的引用参数析构并重建源对象，外层变量的显式引用闭合不足以排除这一情况。

## 决策

`record_copy_check` 使用同一个私有结构解析器恢复精确声明、实参和字段读取。
独立 `inspect_effects` 仅输出结构路由和狭窄效果分类，不调用字段值检查器，
不假设源活跃、字段可读或正常返回；未支持的声明效果使其返回unknown。
原 `check` 在fresh结构解析后添加动态前提，才将映射解释为条件整数值相等。
保留原值接口对属性的较宽支持，值checked不蕴含效果checked。

## 边界

结构检查仍信任完整Clang AST和外部整数ABI；不是机器码验证。它不建立动态
源目标非重叠、生命周期、历史值保持、其他调用及析构的效果。capture协议的
alive前提本次不删除。未来生命周期组合必须另外核验所需义务，不能只消费
父报告status，也不能增加同义的“无别名／值保持”外部布尔来替代分析。

后续增加独立的`object_boundary`子报告：在fresh结构成功后限定complete自动
目标/精确按值参数，并要求正面implicit trivial析构证据。它只提供条件抽象
对象边界和该record析构分类，不改变父结构或字段值报告的scope；外围cleanup、
物理ABI存储及历史保持仍未建立。此子报告失败不隐式改写旧父报告成功状态，
使用它的后续门控必须显式检查其status。

2026-09-30延伸：`object_use_closure.inspect_uses`将显式引用结构与初始化
数值检查分离。真实HIP对象初值已有另一条fresh守卫分析来源，不能为获取
引用清单而再要求调用者手填selection_domains。新入口无域/旧报告参数，
与旧inspect_structure共用私有结构实现，但不执行初始化值检查；初始化
值、效果、cleanup和完成均显式未建立。旧入口不改变。后续组合仍须fresh
绑定同一对象和根，并检查构造到各复制点的历史，不能把结构接口当成绕过。
