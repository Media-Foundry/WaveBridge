# 语料与基线协议

当前登记一个development案例：llama.cpp RMSNorm手工HIP standalone，已有九个
确定性输入的设备基线记录及受限源码分析；完整研究验收尚未通过。
`examples/qdot/` 是接口验证模型，不能作为真实 ML workload 数量计入覆盖统计。

`corpus.json`区分原始TU、手工HIP及CUDA adapter。llama-rmsnorm的早期intake中
仍有历史待办字段，当前状态以corpus和带日期证据为准。
第二仓库vLLM RMSNorm的首次固定分析器评估保留在
[intake协议](intake/vllm-rmsnorm-protocol.md)及原始工件中。此后它已反复用于
分析器开发和调试，当前属于开发反馈输入，不能把后续结果算作新的未见holdout。
它尚未以完备执行案例收入corpus.json；当前登记数量不因此增加。
`intake/`记录是人工筛选资料，不是自动恢复器的关系输入或oracle。

## 纳入语料

每个案例在 `corpus.json` 中记录：唯一 ID、上游 URL、精确提交、文件与符号、文件 SHA-256、许可证、代码谱系、ML 场景、源语义和 launch、人工关系 oracle、外部数值/输入协议、原样或修改状态及补丁。

按代码谱系拆分开发与留出集，同源变体不得跨集合形成泄漏。人工 oracle 单独保存；自动分析器不能读取留出集 oracle。纳入失败和排除原因同样登记。

首批方向是融合量化 GEMV、带辅助广播的 norm/softmax，以及一个有真实成员语义的 ballot 路由案例。这些是检索目标，不是已找到或已支持的工作负载。

## 基线

| 基线 | 比较目的 | 必要限制 |
| --- | --- | --- |
| SCALE 兼容模式/规范 logical32 实现 | 正确兼容之后是否仍有价值 | 可用性、版本、配置与正确性先核实 |
| Polygeist | 普通重定向与子组关系分析的差异 | 共同适用输入；精确失败阶段与最小案例 |
| CKTI | CUDA 到高层 IR 的覆盖范围 | 获取实现/全文或明确标为不可核实 |
| 强人工参数化实现 | 可达到性能与工程成本 | 相同目标、后端和调优预算 |
| 人工关系 + 相同后端 | 自动恢复的独立价值 | 禁止把后端差异归给分析器 |
| 相同关系 + 既有变换机制 | 新增子组变换的独立价值 | 输入关系与搜索预算保持一致 |
| 普通测试筛选 | checker 的额外错误拦截价值 | 同一候选池、同一预算、独立错误 oracle |

不可安装、无法运行或许可受限的基线标记 `unavailable` 并说明原因，不算作工具失败或零性能。不得为制造差距故意使用不正确的 native 基线。

## 指标分母

同时报告总案例、支持域内案例、接受、拒绝、未知和每类原因。有效接受率定义为独立 oracle 判定为正确且在声明域内的候选中，被 checker 接受的比例；错误放行率定义为独立 oracle 判为错误的候选中，被 checker 接受的比例。报告绝对计数和未知标签数；没有可靠 oracle 时不填这两个率。

恢复覆盖、模型检查通过、源码转换成功、数值测试通过和设备执行成功分别记录。性能只比较正确候选，注明 warmup、样本、统计量和测量波动。人工耗时/补丁量属于工程成本记录，未经专门设计不能称为开发者用户研究。
